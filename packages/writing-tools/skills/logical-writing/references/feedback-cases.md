# 합성 피드백 사례

추상 규칙만으로 수정 방향이 안 보일 때 읽는다. 모든 상황과 수치는 설명용으로 새로 만든 예시이며 실제 관측이나 성과가 아니다. 각 행은 독립적인 사례다. 실제 문서에서는 수정 예시의 주장도 근거로 확인해야 한다.

| 사례 | 부족한 문장 또는 구성 | 피드백과 수정 예시 | 교훈 |
| --- | --- | --- | --- |
| 불필요한 절차 확인 | “필수 검토 절차를 모두 준수했다.” | 절차 준수 자체가 판단 기준이 아니고 후속 설명에도 쓰이지 않으면 삭제한다. 규정 준수가 판단 기준이면 해당 근거를 남긴다. | 뒤의 설명 또는 독자의 판단에 필요한 문장만 남긴다. |
| 관측에서 행동으로 도약 | “요청이 밀렸으므로 담당 인원을 늘렸다.” | 먼저 접수·처리 기록으로 지연을 확인하고, 접수 집중과 처리 지연을 구분한다. 처리 단계의 인력 부족이 뒷받침될 때 증원을 제안한다. | 관측·진단·가설·행동 사이의 연결을 쓴다. |
| 설정별 결과 누락 | “이 대기 간격이 가장 좋았다.” | 비교한 간격별 대기 시간과 처리량을 표로 제시하고 선택 기준을 설명한다. 결과를 본 뒤 추가한 비교라면 사후 분석임을 표시한다. | 조건별 결과와 결과의 의미를 함께 보인다. |
| 비교 조건 불명확 | “새 절차가 더 빨랐다.” | 같은 종류의 요청, 같은 담당 인원, 같은 측정 기간에서 절차만 바꿨는지 밝힌다. 조건이 다르면 비교의 한계를 남긴다. | 기준·변경·고정 조건과 판단 기준을 명시한다. |
| 갑자기 등장한 개념 | “이제 여러 담당자의 판단을 평균한다.” | 먼저 판단을 결합하는 이유, 결합 대상과 방법을 소개한 뒤 평균 결과를 제시한다. | 개념의 필요성과 뜻을 먼저 소개한다. |
| 지표의 방향만 제시 | “수정 횟수가 줄었다.” | “수정 횟수 감소는 재작업 부담을 낮춘다. 단, 검토 생략 때문이 아닌지는 누락률로 함께 확인한다.”처럼 독자의 판단과 연결한다. | 높고 낮음이 왜 중요한지 설명하되 인과를 과장하지 않는다. |
| 자작 용어 | “흐름 스위치를 돌려 업무 발사 속도를 높였다.” | “접수 우선순위를 바꿔 시간당 처리 건수를 늘렸다.”처럼 행동과 측정 대상을 쓴다. 해당 분야의 표준 용어가 있으면 확인해 쓴다. | 뜻이 불명확한 비유 대신 구체적·표준적 용어를 쓴다. |
| 서로 다른 집합의 비율 | “접수 요청의 대부분을 완료했다.”라는 설명에 접수 건수와 전체 완료 건수만 붙였다. | 합성 예시: “이번 기간 접수는 40건이고 전체 완료는 28건이다. 완료에는 이전 기간 접수도 포함되어 이번 접수의 완료율은 아직 계산할 수 없다.” | 분자·분모를 명시하고 다른 집합을 부분과 전체로 쓰지 않는다. |
| 서로 다른 가설 합치기 | “안내문 길이와 배치 문제를 이 조사로 모두 해결했다.” | 길이가 이해도에 미치는 영향과 배치가 발견 가능성에 미치는 영향은 질문과 근거가 다르다. 각각의 결과와 미확인 부분을 나눠 쓴다. | 다른 가설은 각각의 근거로 판단한다. |
| 방어적인 무주장 | “더 좋다는 증거도 더 나쁘다는 증거도 없다.” | 아무도 묻지 않은 우열이면 삭제한다. 우열이 판단 대상이면 “현재 비교 자료로는 선택할 수 없으므로 동일 조건에서 비교한다.”라고 쓴다. | 무의미한 방어는 덜고 판단에 필요한 불확실성은 남긴다. |
| 내부 사정으로 정당화 | “발표에 보여 줄 내용이 필요해서 이 방식을 골랐다.” | 독자에게 중요한 기준인 유지 비용·사용성·안전성 중 어떤 근거로 선택했는지 제시한다. 근거가 없다면 새 이유를 지어내지 않는다. | 선택에는 외부에서 검토 가능한 이유가 필요하다. |
| 분석 방법의 근거 누락 | “자동 분석 도구로 의견을 분류했다.” | 어떤 관측에서 질문이 생겼는지, 무엇을 입력했고 어떤 설정·판정 기준을 썼는지, 방법의 신뢰성과 한계를 설명한다. 뒤늦게 찾은 방법 근거는 사후 근거로 구분한다. | 분석의 동기·방법 타당성·수행 조건을 쓴다. |
| 시행착오의 무질서한 나열 | 시도한 순서대로 모든 변경을 나열했다. | 예를 들어 “업무 배분”과 “처리 절차”가 실제 판단 축이라면 두 논점 아래 근거를 묶는다. 나누는 이유를 설명하고 두 축에 맞지 않는 사례는 별도로 다룬다. | 핵심 논점으로 구조화하되 분류를 강제하지 않는다. |
| 참고 사례의 내용 복사 | 참고 문서의 결론과 한계 목록을 그대로 옮겼다. | 결론 → 비교 근거 → 다음 선택이라는 구성만 빌리고, 현재 문서의 근거와 판단을 바꾸는 한계로 채운다. | 구성은 빌려도 내용·근거는 복사하지 않는다. |
| 요약 없는 결과 나열 | “전화 문의는 늘고 방문 문의는 줄었다.”로 끝냈다. | “문의 경로가 바뀌었으므로 대응 인력 배치를 검토한다”는 명제로 연결하되 집계 정의와 후속 정정을 확인하고 계절 변화 같은 다른 설명도 검토한다. | 핵심 명제로 추상화하고 원자료·반증을 추적한다. |

적용할 규칙은 [SKILL.md](../SKILL.md), 새 사례를 남기는 방법은 [피드백 로그](feedback-log.md)를 따른다.
