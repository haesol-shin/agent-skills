# 관련 역량과 역할 분담

다른 글쓰기·검토 역량과 함께 작업하거나 문제가 이 skill의 범위를 벗어날 때 읽는다. 아래는 필요한 역할이지 특정 제품이나 설치 의존성 목록이 아니다. 사용할 수 있는 지침의 실제 범위를 확인한 뒤 역할을 나눈다.

| 필요한 역할 | 맡기는 질문 | 이 skill과의 경계 |
| --- | --- | --- |
| 사실·출처 검증 | 출처가 실제로 존재하며 원문·수치·인용이 주장과 일치하는가? 이후 정정이나 반증이 있는가? | 논리적으로 잘 연결된 문장도 사실과 다를 수 있다. 구조 검토를 사실 검증으로 대신하지 않는다. |
| 평가·실험 설계 검토 | 비교가 같은 조건에서 이루어졌는가? 평가 대상 정보가 설계나 선택에 새어 들어갔는가? | 이 skill은 비교 조건을 쓰게 하지만 실험의 타당성을 자동으로 보증하지 않는다. |
| 명료한 문장 스타일 | 능동적인 주어, 구체적인 표현, 간결한 문장인가? | 구조와 논리를 정한 뒤 표현을 다듬는다. 압축 때문에 근거와 중요한 제약을 없애지 않는다. |
| 문서 유형별 구성 | 논문·보고서·설계 문서·발표의 독자 기대와 필수 형식은 무엇인가? | 유형과 제출 형식의 요구를 존중하면서 결론과 근거의 연결을 지킨다. |
| 맥락 없는 독자 검토 | 무엇을 이해했고, 어디서 막혔으며, 무엇을 추측해야 했는가? | 작성자의 의도를 미리 설명하지 말고 문서 자체로 읽게 한다. 실제 오해를 수정한다. |
| 공개 전 정보 검토 | 개인 정보, 원자료, 비공개 조직·시설·경로가 남아 있는가? | 공개 사례는 새로 만든 합성 예시만 사용한다. 표현 교정은 공개 가능성 검토를 대체하지 않는다. |

이 파일은 외부 문헌이나 개별 도구의 성능을 주장하지 않는다. 외부 자료를 새로 추천하려면 실제 자료를 열어 적용 범위와 주장을 확인하고, 공개 가능한 출처와 확인 내용을 남긴다.
